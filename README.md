# npa-pipeline

Инструмент для работы с официальными нормативно-правовыми актами (НПА) РФ. Состоит из четырёх этапов, разрабатываемых последовательно.

## Этапы

1. **Скачивание** (в разработке) — автоматический поиск и загрузка оригиналов документов через API `publication.pravo.gov.ru`, без ИИ в рантайме. Отдельным расширением — справочники ИТС/НДТ через `burondt.ru` (метод откалиброван, не запрещён `robots.txt`). План: [`docs/stage1-plan.md`](docs/stage1-plan.md), справочник API: [`docs/api-reference.md`](docs/api-reference.md).
2. **История изменений и статус документа** (не начато) — для документа, найденного на этапе 1: список актов, которые его изменили, и статус — действует / не действует / чем отменён. Два источника: `ips.pravo.gov.ru` (надёжный, но покрывает только 5 высших органов — Президент, Правительство, Госдума, Совет Федерации, Конституционный Суд) и `docs.cntd.ru` (покрывает всё остальное, включая ведомственные приказы и региональные акты, но использование заблокировано открытым правовым вопросом — `robots.txt` источника явно запрещает автоматический поиск, нужен ответ от АО «Кодекс»). План: [`docs/stage2-plan.md`](docs/stage2-plan.md), справочник источников: [`docs/status-sources-reference.md`](docs/status-sources-reference.md).
3. **OCR** (не начато) — распознавание сканов в текст/DOCX.
4. **Приёмка в нормативную базу** (не начато) — размещение акта, верификация реквизитов, карта влияния.

## Установка

```bash
pip install -e ".[dev]"
```

## CLI

```bash
# один раз: справочник органов (~4000 записей) в data/npa.db
npa refresh-authorities

# поиск и скачивание (метаданные → БД, PDF → downloads/)
npa fetch --authority "Президент Российской Федерации" --number 310-ФЗ --date 2025-07-31

# если известен eoNumber
npa fetch --eo 0001202507310060

# только поиск, без PDF (found/ambiguous всё равно пишутся в БД)
npa fetch --authority "..." --number 402 --date 2016-07-19 --no-download

# перенос старых JSON-sidecar в БД (если остались после ранних версий)
npa import-json --out-dir downloads --delete-json

# ИТС/НДТ (burondt.ru) — отдельный источник, свой кэш и свой поиск (см. docs/stage1-plan.md)
npa refresh-its --full-rescan          # первый полный обход диапазона (без лимита — займёт время)
npa refresh-its --max-requests 300     # инкрементальное чанкованное обновление — резюмируется само

npa fetch-its "ИТС 28-2021"            # точное обозначение
npa fetch-its 2021                     # все версии за год
npa fetch-its "ИТС 53"                 # все версии номера без года, новые сначала
```

Результат — JSON со статусом (`found`, `not_found`, `ambiguous`, …). PDF сохраняется в `downloads/` с человекочитаемым именем, например:

`Постановление Правительства Российской Федерации от 31_05_2019 N 691.pdf`

Реквизиты, подписанты, sha256 и путь к файлу — в `data/npa.db` (таблицы `documents`, `document_signatories`, `document_files`).

## Библиотека

```python
from datetime import date
from npa_pipeline import Query, fetch_document

result = fetch_document(
    Query(
        authority_name="Президент Российской Федерации",
        number="310-ФЗ",
        date=date(2025, 7, 31),
    )
)
print(result.status, result.eo_number, result.pdf_path)
```

## Веб-интерфейс (для проверки)

```bash
pip install -e ".[web]"
npa-web
# откройте http://127.0.0.1:8765
```

Переключатель типа документа (НПА / ИТС/НДТ) сверху формы показывает свой набор полей —
у каждого источника свой способ поиска, общей формы для обоих не может быть.

- **НПА**: поиск по названию органа (с автодополнением из локального кэша) + номеру +
  дате. `eoNumber` и GUID органа в форме не показываются — это внутренние
  идентификаторы, которые обычный пользователь не знает заранее; GUID заполняется
  автоматически при выборе органа из подсказки. Найденный PDF открывается прямо в
  новой вкладке браузера (не скачивается принудительно на диск).
- **ИТС/НДТ**: поиск по точному обозначению, по одному году или по номеру без года
  (тогда результат — список всех версий, новые сначала, у каждой — свои файлы
  «справочник»/«приказ» со ссылками на открытие).

Кнопка обновления кэша — одна, под счётчиком записей сверху страницы, её подпись и
поведение меняются вместе с выбранным типом документа: для НПА это быстрый одиночный
запрос, для ИТС — полный обход диапазона burondt.ru (~2550 запросов, десятки минут),
поэтому вынесена отдельно от кнопки «Найти» и сопровождается прогресс-баром и явным
предупреждением перед запуском. Процент показывается только после того, как хотя бы
один полный обход подтвердил, где реально кончается диапазон — до этого прогресс
неопределённый, а не подставленное число.

## Статус

Этап 1 реализован для обоих источников: библиотека + CLI + веб-интерфейс + единая
локальная БД, отдельно для документов НПА (`publication.pravo.gov.ru`) и справочников
ИТС/НДТ (`burondt.ru`) — у каждого источника свой алгоритм поиска и свой набор таблиц,
общей схемы для них нет намеренно (реквизиты и структура карточек слишком разные —
подробное обоснование в `docs/stage1-plan.md`, раздел «Расширение: документы ИТС/НДТ»).
